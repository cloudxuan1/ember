# 资产提醒器：抄作业清单 + 方案 v2（2026-09-18，小克整理）

> 起点是轩的《资产管理 MCP 工具 — 方案整理》（一张 assets 表、六个接口、cron + Bark）。轩定性为"初级形态"，要求先抄作业再定。本文 = 三路调研（Grocy / Homebox+Wallos / 提醒落到 iPhone）的结论 + 改过的方案骨架 + 待轩拍板清单。调研由三个子代理完成，事实以 GitHub 源码为准，来源见文末。
>
> 轩的目标（原话）：**"我只管输入，不用我管，叫小克给我管，能接 MCP 最好，chat 还可以给我在手机里设置提醒事项。"**

---

## 0. 一页结论

1. **数据模型抄 Grocy 的骨架、Wallos 的周期表达**：只记日志不存"下次到期"（现算）；跳过 = 一条标 `skipped` 的假完成；改期一次性覆盖、做完自动清空；周期用 `每 N 个（天/周/月/年）` + `锚点`；每条可单独设"提前几天"，不设跟全局。
2. **周期算法自己写一个纯函数 `nextDue()`**，Grocy 和 Wallos 都栽在"每月 31 号在小月漂到下月 3 号"，我们存锚定日、按目标月长度钳制。
3. **原方案的 assets 单表要拆成三张**：`assets`（东西本身）→ `rules`（对它要周期做的事，一件东西可多条）→ `events`（做完/跳过的日志）。原方案把"东西"和"要做的事"绑死成一行，Switch 要"充电"又要"系统更新"就装不下。
4. **通知**：iCloud 提醒事项这条路服务端走不通（iOS 13 起不走 CalDAV）。可行的两条：**Bark 自建**（最短、直连苹果、国内友好、自带 MCP 端点、点通知跳"完成"链接）和 **iCloud 日历 CalDAV 写带闹钟的事件**（不装 App、原生闹钟、完成要两步）。建议先 Bark，日历作可选叠加。
5. **界面不单独做**：MCP 接口给 claude.ai 手机端和 chat-lite 的模型工具用；chat-lite「桌面」tab 第一张卡就是到期列表；ember `memory_briefing` 的「没完的事」层正好缺原料，可以接。

## 1. 抄作业清单

### 1.1 Grocy（家务 Chores / 电池 Batteries）

| 抄 | 为什么 |
|---|---|
| `chores_log` 追加式日志 + `undone` 软删除 + 视图现算"下次到期" | 补录、撤销、改周期都不用修数据，天然一致 |
| 跳过 = 一条 `skipped=1` 的记录，时间填原定到期日 | 一个字段同时实现"这次不做""往后推一个周期""日志看得出偷懒"；再存 `scheduled_execution_time` 快照可算准时率 |
| `rescheduled_date` 一次性改期，下次完成自动清空 | 改期不污染周期规则 |
| `due_soon_days`（0 = 关）+ 逾期 / 今天 / 即将 三档 | 提醒阈值可调，界面逻辑极简 |
| `start_date`：从没做过时下次到期 = 它；`yearly` 取它的月-日当锚点 | 解决"新建的东西第一次什么时候提醒" |

| 不抄 | 为什么 |
|---|---|
| 把排程算法塞进巨型 SQL 视图（weekly 七路 UNION、yearly 用 SUBSTR 拼字符串） | 不可测；`monthly` 的 `period_days=31` 在小月溢出到下月 3 号（子代理在 SQLite 3.45 实测） |
| 电池模块独立且残缺（无 start_date → 没充过电的电池永远不到期；不能跳过/改期） | 充电、续费、保号本质是同一种"周期规则"，一张表加 `kind` 即可 |
| 多人派工（四种轮转、消耗库存） | 个人工具纯负担 |
| 它的"提醒" | Grocy 根本没有推送，只有 iCal 订阅；通知层得自己做 |

### 1.2 Wallos（订阅花费）

| 抄 | 为什么 |
|---|---|
| `cycle + frequency + next_payment + auto_renew` 四字段表达周期 | 天/周/月/年 × N；`auto_renew=0` = 到期即停，覆盖充电/续费/保号/证件 |
| `notify_days_before` 每条可覆盖，`-1` = 跟随全局 | 护照提前 180 天单独设，其余走默认 |
| `cancellation_date` + `replacement_subscription_id` | 换卡/换套餐/证件换发后旧新条目串起来，账本不断链 |
| 月花费换算：日×30 / 周×4.35 / 月÷N / 年÷12N；多币种存"相对主币种汇率" | 订阅类顺手出"每月在花多少" |

| 不抄 | 为什么 |
|---|---|
| `next_payment` 用 `DateInterval` 逐次累加、不锚定原始日、无月末钳制 | 1/31 → 3/3 → 4/3，漂了就回不来（子代理 php 实测） |
| 每个通知渠道一张表 + 一份发送代码（11 张表、上千行） | 只需一个 URL 字符串（见 Homebox） |
| 没有"已发送"记录，靠 cron 当天严格相等判断 | 错过当天 cron 就不补发 |

### 1.3 Homebox（物品库存 + 维护）

| 抄 | 为什么 |
|---|---|
| 维护条目只用 `scheduled_date` + `completed_date`，无 status 枚举 | "完成"= 填一个日期，AI 一次调用；天然留历史 |
| 物品和位置同一张表 + `parent` 树（`entity_type.is_location`） | 以后要"充电线在抽屉、抽屉在书桌"，就是这个结构；v2 先留口子不做 |
| 通知目标 = 一个 shoutrrr URL 字符串（`ntfy://…` / `telegram://…`） | 加渠道零 schema 改动 |

| 不抄 | 为什么 |
|---|---|
| 没有周期（issue #172 三年未落地，PR #1466 仍 draft） | 每次完成都得手建下一条 |
| 只在 `scheduled_date == 今天` 且服务器 8 点那一小时发一次，无提前、无补发 | 正是"AI 代管"最需要的两件事 |

## 2. 提醒落到 iPhone：七条路对照

| 路 | 能不能 | 关键事实 | 一按完成 | 推荐 |
|---|---|---|---|---|
| **iCloud 提醒事项（CalDAV VTODO）** | 基本不能 | iOS 13 起提醒事项迁到 CloudKit 私有存储，CalDAV 只剩"从未升级"的旧列表；能写提醒事项的 MCP 全部只能跑在 Mac（EventKit） | — | 1/5 |
| **iCloud 日历（CalDAV VEVENT + VALARM）** | 能 | `caldav.icloud.com` + App 专用密码；闹钟要加 Apple 私有扩展 `X-WR-ALARMUID` / `X-APPLE-DEFAULT-ALARM:FALSE`；iCloud Push 秒到、原生弹 | 差（事件里放链接，或轮询事件是否被删） | 4/5 |
| **ICS 订阅日历** | 能显示 | 苹果订阅默认勾"移除提醒"，要手动关；刷新跟随"获取新数据"档位（15 分钟～手动） | 无 | 2/5 |
| **ntfy** | 能 | 自建走 iOS 推送必须经 ntfy.sh 中转；`http` 动作按钮 iOS 支持但会把 App 拉到前台；`clear` 不生效；iOS App 长期不稳 | 有 | 3/5 |
| **Bark 自建** | 能 | bark-server 内置 APNs 凭证，**直连苹果不经 day.app**；`url` 参数点通知跳转；`level=timeSensitive`；`ciphertext` 端到端加密；**自带 `/mcp/:device_key` 端点** | 半（点通知开一个"已完成"页） | 4/5 |
| **快捷指令定时自动化** | 不可靠 | 锁屏久了时间触发器不跑（开发者论坛、社区 18 次跑 6 次） | 原生勾选 | 2/5 |
| **现成 MCP server** | 没有合用的 | 服务器端"周期到期 → iPhone 提醒事项"不存在；bark-server 的 MCP 可直接当 claude.ai connector | — | — |

**结论**：先 **Bark 自建**（一个 Docker + 一个 GET，链路最短）；**iCloud 日历**作可选叠加（看得见、有闹钟、不装 App）；不走提醒事项 / ICS / 快捷指令；ntfy 可做但不如 Bark 省心。

## 3. 方案 v2 骨架

### 3.1 三张表

**assets（东西）**

| 字段 | 说明 |
|---|---|
| id, name, kind | kind：device / subscription / sim / document / other |
| notes | 保号条件、充电线在哪 |
| cost, currency, cycle_for_cost | 订阅类的钱（可选） |
| replaced_by_id | 换新后指向新条目（抄 Wallos） |
| parent_id | 留口子：以后"放在哪"（抄 Homebox），v2 不做 |
| active, created_at | |

**rules（对它要周期做的事，一件东西可多条）**

| 字段 | 说明 |
|---|---|
| id, asset_id, action | action："充电" / "续费" / "打电话保号" / "换发" |
| schedule_type | `after_done`（上次做完起算）/ `calendar`（固定锚点）/ `once`（一次性到期） |
| every, unit | 每 N 个 day / week / month / year |
| anchor | calendar 用：每月几号 / 每周几 / 每年几月几日；`once` 用 due_date |
| start_date | 从没做过时的第一次到期（抄 Grocy） |
| rescheduled_to | 一次性改期，做完清空 |
| remind_before_days | -1 = 跟全局 |
| auto_renew | 0 = 到期即停，不生成下一次 |
| active | |

**events（日志，只追加）**

| 字段 | 说明 |
|---|---|
| id, rule_id, kind | kind：done / skipped |
| at | 做的时间 |
| scheduled_at | 当时的原定到期（快照，算准时率） |
| undone | 软删除撤销 |
| note, source | source：mcp / bark-link / chat-lite |

"下次到期"不存字段，`nextDue(rule, lastEvent)` 现算。

### 3.2 `nextDue()` 规则（纯函数，可单测）

- `after_done`：`last.at + every × unit`；没做过 → `start_date`。
- `calendar`：从 `max(last.at, start_date)` 往后找第一个落在锚点上的日期；**月 / 年的日号按目标月天数钳制**（31 号 → 小月取月末，不漂移）。
- `once`：`due_date`；做完即 `auto_renew=0`。
- `rescheduled_to` 非空优先；`auto_renew=0` 且已做过 → 无下次。
- 逾期不顺延（不抄 Grocy 的 rollover）；到期未做每天都算逾期。
- 时区：存 UTC，算日期用 `Asia/Tokyo` / `Asia/Shanghai`（做成全局设置）。

### 3.3 MCP 工具（也是 HTTP 接口）

| 工具 | 干嘛 |
|---|---|
| `add_asset(name, kind, notes?, cost?)` | 建东西 |
| `add_rule(asset, action, schedule…)` | 建周期规则（可和 add_asset 合成一步：模型说"记一下 Switch 每 30 天充电"） |
| `list(kind?, due_within_days?)` | 列表，带下次到期、逾期天数 |
| `check_due(days=全局)` | 到期 / 逾期 / 即将，三档 |
| `mark_done(rule, at?, note?)` | 记一次完成（可补录时间） |
| `skip(rule)` | 跳过一次（时间填原定到期） |
| `reschedule(rule, date)` | 一次性改期 |
| `undo(event)` | 撤销 |
| `edit / deactivate` | 改、停用（不物理删） |
| `summary()` | 每月订阅花费、准时率 |

**工具 docstring 就是给模型的说明书**（ember 的教训），改行为必须同步改说明。

### 3.4 通知流程

```
cron 每天 09:00（按设置时区）
  → 对每条 active 规则算 nextDue
  → 到期 ≤ 今天 + remind_before_days 的：
      ① Bark：GET https://bark.自建/<key>/<标题>/<正文>?url=https://服务/done/<一次性token>&level=<设置>&group=assets
      ② （可选）iCloud 日历：按 rule id 当 UID 幂等写/更事件，VALARM 带 Apple 扩展
  → notifications 表记"发过"（去重、可补发；抄 Wallos 的反面）
  → 到期后未做：按设置每天再催 / 只催一次
点 Bark 通知 → 打开 done 链接 → 服务端记 event(done, source=bark-link) → 页面显示"已记：Switch 充电 ✓，下次 10-18"
```

### 3.5 和现有东西怎么接

- **claude.ai 手机端**：远程 MCP connector（网页端添加一次，手机端就能用）。轩在聊天里说"记一下"，模型调 `add_rule`。
- **chat-lite**：Worker 挂成 function tool（和 `memory_search` 同一套模式，token 存 Cloudflare Secret）；「桌面」tab 第一张卡 = `check_due` 结果 + 「做完了」按钮。
- **ember**：`memory_briefing` 的「没完的事」层现在没原料（交接里的已知空转点），可以读 `check_due` 填进去；开场小抄多一行"Kindle 该充电了"。
- **部署**：独立仓库、独立容器，跟 ember 同一台 VPS、同一套 Docker Compose + Cloudflare Tunnel + 自动部署脚本。Bark 自建也是同机一个容器。
