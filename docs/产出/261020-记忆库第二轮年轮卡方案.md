- **审核 + VPS 上的活：Codex**（审 diff；在 VPS 上用备份拷贝试跑迁移、部署后核对、补算指纹）。CC 碰不到 VPS，凡是要在服务器上跑的都归 Codex。

## 一、为什么改

- 原来的主题、层级、五种关系、起止日期，存的人（包括以前的小克）都不知道该填什么，填得五花八门：主题有时是窗口名，有时是小标题，有时是分类，跟标签打架；层级只在关键词搜索里多加 1 分；关系里只有"取代"真起作用，其他是导入时程序自动抽的。
- 一条记忆只有一个语义指纹，长记忆里埋着的心情会被整条的意思冲淡，按心情搜偏弱。
- 事情是一点一点往前走的（计划 → 结果），现在的结构要么拆成两条再连线，要么只能改日期、按日期筛就丢了老日子。

## 二、轩看得见的变化

- **一件事一张卡**：卡上有标题，下面一圈一圈是**年轮**（哪天、发生了什么）。有新进展就**补一圈**，不新开一条。
- **三个抽屉**：
  - **长期**：关于轩的常识，按主题一张卡（我、我们、偏好、习惯、家人、朋友、工作、身体、爱好……）。
  - **日常**：发生过的事、心情小日记、画下的饼。
  - **项目**：技术笔记。
- **便利贴**照常随便贴；网页上把常用的几张摆成一排"文件夹"，点进去就是贴了这张的所有卡。
- **⭐收藏**：每张卡一颗星，网页上有"收藏"入口。
- 卡上显示**来自哪里**（老记忆的来源文件 / 小节）。
- **饼**用四张专用便利贴：`筑巢饼`（建家、项目）、`连理饼`（两个人之间）、`养成饼`（个人成长）、`远方饼`（要去的地方）；兑现了加贴 `吃到了`。还没决定做不做的灵感贴 `面团`（面团 → 饼 → 吃到了；决定要做了，就把 `面团` 换成对应的饼）。
- 主题、层级、关系都拿掉，存一张卡只剩：标题、日期、内容、便利贴、⭐、抽屉。

## 三、规矩（写进 MCP 工具说明）

1. 同一件事的后续 → **补一圈**；一件新的事 → **新卡**；心情小日记一天一张。
2. 分量重的结果（值得单独记的时刻）→ 新建一张卡，原卡补一圈"见 #编号"。
3. **年轮的日期 = 这一圈的事发生（或说出口）的那天，不能写未来的日子**。计划要在哪天做，写进这一圈的正文里。所以：有某一圈 = 那件事已经发生；饼兑没兑现，看有没有贴 `吃到了`。
4. 日期写具体日期或只到月，不写"最近""下周"这种相对说法（沿用现规则）。
5. 存的时候顺手贴一两张心情便利贴（着急、开心……）。
6. **专用便利贴名单**：`筑巢饼` `连理饼` `养成饼` `远方饼` `吃到了` `面团`，只能贴在饼和灵感上。`面团` 不进开场、不催，只是存着免得灵感丢了。
7. 长期抽屉只放常识，不放事件；常识变了就在那张卡上补一圈。

## 四、要干的事（五个 PR，一个 PR 一件事，按顺序做）

- 卡片日期 = 最新一圈的日期（补圈、改圈、删圈后同步 `memories.date`）。
- 迁移脚本（只加不删、可重复跑、跑第二遍不重复搬）：
  - 每条记忆的 `content` 原样抄成第一圈，日期照旧；`content` 列保留。
  - `topic` 只被一条记忆用 → 变成 `title`；被多条共用 → 并进 `tags`（已有就不加）；空的 → `title` 留空（网页显示正文开头）。
  - `tier = 'anchor'` → `starred = 1`（轩已定：全部变⭐）。
  - 来源（`memory_sources`）、上一版（`memory_history`）、最近动静（`activity_log`）、软删除，全部照旧。
- 新设置 `ke_can_star`（小克能不能点⭐），**默认开**（轩已定：小克可以点）。设置页加一个开关，样子照现有的"小克能不能删"那个做，不另起新样式。

### PR2 搜索（大改动，Codex 审）

- **按圈算指纹**：每一圈一个指纹；太长的圈按段落（空行）切，单段太长再按固定长度切，段与段之间稍微重叠，免得一句话被切在中间。搜的时候哪一段对上，整张卡就算命中，结果里带上命中的是哪一圈。
- 关键词腿同时搜 `title`、`tags`、每一圈的内容。
- **按日期筛**：任意一圈的日期落在范围里，这张卡就算（只到月的日期按整月算，沿用现规则）。
- **按便利贴筛**：新增参数，标签按逗号拆开后整张比，完全一样才算，不做子串匹配。口令 `饼` = 四张饼便利贴任一；可以再叠一个"排除 `吃到了`"，用来看还没兑现的饼。
- 默认搜索范围：日常 + 长期；项目抽屉要显式指定；`"all"` 跨全库，沿用现规则。
- 语义腿不可用时退回关键词，沿用现规则。
- 旧的整条指纹表先留着当退路，PR5 再删。
- 上线后按圈补算指纹，由 Codex 在 VPS 上跑。

## 五、风险和兜底

- **搬家搬错**：先在拷贝上试跑；核对卡数 = 记忆数、第一圈数 = 记忆数、标签只多不少；随机抽 5 张，第一圈跟原 `content` 逐字比对。
- **搜索变差**：上线前后跑同一套体检题（小克在聊天里给，不进仓库），对比名次。
- **指纹重算**：要花一点 embedding 费用和时间；算的过程中语义腿会暂时不准，关键词照常可用。
- **工具变了**：claude.ai 的 connector 会缓存旧工具，上线后要刷新工具；旧参数兼容兜一层。
- **部署**：容器重启，停几秒到一分钟。

## 七、怎么测

- 迁移：数量核对 + 逐字抽查，见第五节。
- 年轮：编一张两圈的卡（一圈 10 月、一圈 11 月），按 10 月筛、按 11 月筛都能出来；补圈后卡片日期变成最新一圈。
- 按便利贴筛：编一张贴了 `连理饼` 的卡，再编一条正文里带"南瓜饼"的；按便利贴搜 `饼` 只出前者；自由搜"南瓜饼"能出后者。
- 分段指纹：编一条很长的卡，把一句心情埋在中间一段，用意思相近但字面不同的话去搜，它要排进前 3。
- 搜索体检：小克在聊天里给的那几题，上线前后各跑一遍。
- 开场简报：编三张卡，一张贴 `连理饼`、一张贴 `连理饼` + `吃到了`、一张贴 `面团`；简报的饼那一层只出第一张。
- 网页：手机上看时间线、⭐、文件夹。
- 坏了：`git revert` 对应 PR；数据问题从迁移前的快照恢复。
