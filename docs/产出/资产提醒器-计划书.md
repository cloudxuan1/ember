## 1. 人话版（轩看这节就够）

**要解决什么**：Switch 该充电了、iCloud 快扣费了、日本电话卡再不打电话就要被注销了、护照快过期了。这些事都是"隔一段时间要做一次"，人记不住。

**做出来是什么样**：
- 你跟我（任何接了这个工具的 Claude）说一句"Switch 每 30 天充一次电"，就完了。
- 到日子，手机弹一条通知"Switch 该充电了"。点一下通知，就算做完，倒计时自动重来。
- 打开 chat-lite 的「桌面」页，一列卡片：每件事还剩几天 / 逾期几天，右边「做完了」按钮，顶上「＋」可以自己加。
- 你加的、我加的，都在同一个本子上。

**东西记在哪**：你自己的 VPS（跑记忆库那台），一个 SQLite 文件，不经过任何第三方。

**跟记忆库的关系**：分开的两个程序，住同一台机器。claude.ai 里多加一个 connector。

**你要定的**（下面第 8 节有表，我都填了建议值）：通知用 Bark 还是写进 iPhone 日历；到期没做要不要每天催。

## 2. 目标与范围

### 2.1 v1 要做到

1. 一件东西 + 一条周期规则 + 做完记一笔，三样都能通过 MCP 增删改查。
2. 每天定时算到期，到期的推到 iPhone（Bark）。
3. 点通知能标记完成。
4. chat-lite 桌面页能看、能加、能点「做完了」。

### 2.2 v1 明确不做

- 物品账本（在哪、保修、序列号、照片）——表里留 `parent_id` 口子，功能不做。
- 多人、派工、分享。
- 花费统计图表（只存金额，出一个"每月订阅合计"数字即可）。
- 写 iPhone 日历（v2 可选叠加）。
- 自己的登录系统（沿用 chat-lite 密码门 + Worker 转发；MCP 走 token）。

### 2.3 硬边界

- 数据只在 VPS 的 SQLite，仓库公开时不含任何真实数据和密钥。
- 不碰 ember 的数据库、MCP、审核台。
- 不上框架、不上打包器（后端 FastAPI + SQLite，与 ember 同款）。

## 3. 使用方式（三个入口，一个库）

| 入口 | 谁用 | 怎么进 |
|---|---|---|
| **MCP** | claude.ai 网页/手机端、Claude Code、chat-lite 里的模型 | 远程 MCP connector（streamable HTTP），路径当密钥，与 ember 同款做法 |
| **chat-lite 桌面页** | 轩手点 | chat-lite Worker 转发到提醒器的 HTTP 接口，token 存 Cloudflare Secret（与记忆库只读接口同款） |
| **Bark 通知里的链接** | 轩点通知 | 一次性 token 的"完成"链接，点开即记一笔 |

三个入口写的是同一个 SQLite。

---

## 4. 架构

```
VPS（与 ember 同机）
├─ 容器 reminder    FastAPI + SQLite（/app/data/reminder.db）
│    ├─ /mcp/<随机路径>/   MCP 工具（见第 6 节）
│    ├─ /api/…             同一套功能的 HTTP 接口（给 chat-lite Worker）
│    ├─ /done/<token>      通知里的"完成"链接
│    └─ 内部定时任务        每天 09:00（设置时区）算到期 → 推 Bark → 记"发过"
├─ 容器 bark-server  自建 Bark（直连 Apple APNs，不经第三方）
└─ Cloudflare Tunnel 复用 ember 的方式，各自子域名，端口不裸露
```

- 定时任务用 APScheduler 跑在 FastAPI 进程里，不依赖系统 cron（容器重建不用重装）。
- 部署：独立仓库，Docker Compose，复用 ember 的自动部署脚本思路（有更新才重建，重建前拍 SQLite 一致性快照）。

## 5. 数据模型（三张表 + 一张通知记录）

**assets（东西）**：`id, name, kind(device/subscription/sim/document/other), notes, cost, currency, cost_cycle, replaced_by_id, parent_id(留口子), active, created_at`

**rules（对它要周期做的事，一件东西可多条）**：
`id, asset_id, action, schedule_type(after_done/calendar/once), every, unit(day/week/month/year), anchor, start_date, rescheduled_to, remind_before_days(-1=跟全局), auto_renew, active`

**events（做过的记录，只追加）**：`id, rule_id, kind(done/skipped), at, scheduled_at(快照), undone, note, source(mcp/ui/bark-link)`

**notifications（发过的通知）**：`id, rule_id, due_at, sent_at, channel, token, acted_at`

原则（抄 Grocy）：**"下次到期"不存字段，现算**；跳过 = 一条 `skipped` 记录；改期一次性、做完清空；撤销是软删除。

`nextDue(rule, lastEvent)` 是一个纯函数，单独测：
- `after_done`：上次做完 + N 单位；没做过 = `start_date`
- `calendar`：从上次做完往后找第一个落在锚点的日期；**月/年的日号按目标月天数钳制**（31 号在小月取月末，不漂）
- `once`：到期日一次；做完即停
- `rescheduled_to` 优先；`auto_renew=0` 且做过 = 没有下次
- 逾期不顺延

## 6. MCP 工具（同时是 HTTP 接口）

| 工具 | 干嘛 |
|---|---|
| `add_item(name, kind, action, every, unit, …)` | 一步建东西 + 规则（模型最常用的一个） |
| `add_rule(asset_id, action, schedule…)` | 给已有东西加第二条规则 |
| `list(kind?, due_within_days?)` | 列表，带下次到期、逾期天数 |
| `check_due(days?)` | 逾期 / 今天 / 即将 三档 |
| `mark_done(rule_id, at?, note?)` | 记一次完成，可补录时间 |
| `skip(rule_id)` | 这次不做，推到下个周期 |
| `reschedule(rule_id, date)` | 一次性改期 |
| `undo(event_id)` | 撤销一笔 |
| `edit(...)` / `deactivate(id)` | 改、停用（不物理删） |
| `summary()` | 每月订阅合计、准时率 |

工具的 docstring 就是给模型的说明书，改行为必须同步改说明（ember 的教训）。

## 7. 通知流程

```
每天 09:00（设置时区）
  → 每条 active 规则算 nextDue
  → nextDue ≤ 今天 + remind_before_days，且今天还没发过：
      Bark：GET https://bark.<自建>/<key>/<标题>/<正文>
            ?url=https://reminder.<域名>/done/<一次性token>&level=<设置>&group=reminder
      notifications 记一笔
  → 到期后仍未做：按"是否每天催"设置决定是否再发，最多 N 次
点通知 → 打开 /done/<token> → 记 event(done, source=bark-link) → 页面显示
        「已记：Switch 充电 ✓ 下次 10-18」
```

v2 可选：同时把到期写成 iCloud 日历事件（CalDAV，带闹钟，不装 App），按 rule id 幂等。

| 阶段 | 内容 | 验收 |

## 10. 安全

- MCP 路径随机长串当密钥（ember 同款）；HTTP 接口 Bearer token；`/done/<token>` 一次性、24 小时过期、只能标记那一条。
- Bark key 和自建服务器地址只在 VPS `.env`，不进仓库。
- 容器端口只绑 127.0.0.1，公网只走 Tunnel。
- 仓库公开：`.env`、`*.db` 永不入库，文档只写"去哪查"。

---

## 11. 风险

| 风险 | 对策 |
|---|---|
| Bark 依赖苹果推送通道，苹果能看到通知标题 | 开 `ciphertext` 端到端加密；标题不写敏感内容 |
| 定时任务那一刻 VPS 没开 | notifications 表记"发过"，下次启动补发当天未发的 |
| 日期算错（时区、月末） | `nextDue()` 纯函数 + 单测覆盖 31 号、闰年、跨年、时区 |
| 多入口同时写 | SQLite WAL 模式 + 单进程，够用 |
| Safari 7 天清数据 | 与本项目无关（数据在 VPS），chat-lite 桌面页只是视图 |
